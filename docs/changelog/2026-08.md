# August 2026

## 2026-08-04 — Scalable platform administration and three-tier billing

- **Change:** Replaced tenant scans/N+1 reads with indexed, cursor-paginated
  business projections and materialized platform metrics. Added payment status
  indexes, billing contacts, audited superadmin management with last-admin
  protection, and stored VAT-inclusive document components. Plans are now
  Biashara (KES 1,000; 1 store/5 users), Growth (KES 2,500; 3/10), and Plus
  (KES 5,000; 10/30).
- **Maintenance:** Dependabot now checks npm and GitHub Actions weekly on
  Mondays. Operational changes are archived monthly with one compact entry per
  day.
- **Rollout:** Deploy infrastructure and this backward-compatible server with
  enforcement unchanged, run `yarn migrate:platform-billing` once with operator
  credentials, then deploy the client. Configure vendor VAT from verified tax
  advice and verify pagination/search, payment review, metrics, plan limits,
  billing contacts, invitations, audits, and last-admin protection.
- **Recovery/status:** Roll back client and server together. The additive
  migration may be rerun; retain projections, indexes, contacts, documents, and
  audits. Reverting plan prices affects only future payments. Implementation is
  complete; production migration and tax review are pending.

## 2026-08-03 — Tenant billing, generated codes, and BiasharaKit APIs

- **Change:** Added tenant plans/trials, manual M-Pesa submissions, immutable
  billing documents, enforcement and reminders, superadmin review/configuration
  APIs, audited standard-plan assignment, and complete tenant discovery without
  exposing operational data. Blank master-data codes now use tenant-scoped
  atomic sequences. Customer errors, emails, and the active-role header use
  BiasharaKit (`x-biasharakit-role`) exclusively.
- **Impact:** Existing tenant billing is initialized additively; generated code
  gaps after failed creates are harmless. Legacy tenants retain
  `legacy-pending-*` policy history rather than false acceptance, and standard
  plan assignment preserves payment/cancellation dates while clearing custom
  overrides after downgrade-limit validation.
- **Rollout:** Apply infrastructure with enforcement disabled, deploy the
  server, run `yarn migrate:billing --rollout-date=YYYY-MM-DD`, provision a
  verified `superadmin`, deploy the client, verify all tenants, and only then
  enable enforcement after legal/tax review and real vendor/Till configuration.
- **Verification/recovery/status:** Check trials, plan limits, restricted staff,
  exports, payments/receipts, worker invocation, platform configuration and
  audits, and generated codes. Disable enforcement to stop restrictions and
  scheduling; retain billing, document, audit, and sequence records. Production
  activation remains pending configuration, migration, and review.

## 2026-08-02 — Checkout controls, Kenyan VAT, and product-unit costing

- **Change:** Added server-enforced payment/customer/markdown policies with
  immutable price snapshots and atomic audits; Kenyan VAT, supplier invoices,
  partial payments, and 2% withholding-VAT estimates; and product-specific unit
  conversions with exact lot values.
- **Why/data:** Product-level conversions replace unreliable universal package
  assumptions. Existing checkout uses safe defaults, historical transaction and
  purchase snapshots remain unchanged, and no historic tax reconstruction is
  attempted.
- **Rollout:** Deploy before the matching client. For every existing workspace,
  run the idempotent `yarn migrate:product-units '<workspace-id>'` command.
- **Verification:** Test disabled payments, required customers, markdown caps
  and VAT recalculation; mixed-rate receiving, sales, Money totals, partial
  payments and withholding splits; representative units, supplier links, draft
  purchase orders, and lot-value totals.
- **Recovery/status:** Removing checkout settings restores safe defaults;
  disabling VAT affects only future transactions. Correct/deactivate bad units
  and relink future supplier orders rather than rewriting history. Active until
  every existing workspace is migrated and verified; this release does not
  submit to eTIMS or file/remit taxes.
